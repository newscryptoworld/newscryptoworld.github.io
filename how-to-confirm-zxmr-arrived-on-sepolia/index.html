How to Confirm zXMR Arrived on Sepolia

Confirm zXMR on Sepolia by checking the bridge transaction, matching the token contract, and verifying the received balance in your wallet or explorer.

Crypto Record EditorialSep 30, 20262 min read

To confirm zXMR arrived on Sepolia, check the completed transaction and verify that the expected token contract credited your wallet. A wallet balance alone is a useful signal, but the transaction record shows which contract sent the tokens, which address received them, and whether the operation succeeded.

The bridge flow has several parts: a request begins the conversion, the bridge process handles the cross-chain step, and a transaction on Sepolia records the token delivery. That final transaction is the receipt to inspect. For the conversion sequence itself, zerofi has the fuller walkthrough; this guide focuses on checking the Sepolia result.

Where can you check a zXMR transfer?

Use a Sepolia block explorer to look up the transaction hash from the bridge interface or your wallet activity. The explorer reads the public chain record and displays the transaction status, destination address, and token events. It works like a public receipt book: the wallet is your account view, while the explorer lets you inspect the recorded transfer.

Open the transaction details and confirm the status is successful. Then inspect the token transfer event, often shown in an ERC-20 transfer section. Check that the recipient is your Sepolia wallet address and that the amount matches the bridge result. A successful transaction by itself does not prove the right token reached the right address; those details matter too.

How do you know the token is the right zXMR?

Match the token contract address, not just the ticker or display name. Token names and symbols can be copied, while the contract address identifies the specific token contract that emitted the transfer. Use the address supplied for the intended Sepolia token in the bridge flow, then compare it character by character with the contract shown by the explorer or wallet.

Check these fields together:

  • Network: the explorer and wallet are set to Sepolia.
  • Status: the transaction completed successfully.
  • Recipient: the transfer event names your wallet address.
  • Token and amount: the contract address and received quantity match the expected result.

If the explorer shows the correct transfer but the wallet does not show zXMR, the token may simply be hidden from the asset list. Add it as a custom token using the verified Sepolia contract address. The wallet then reads that contract’s balance for your address. A displayed symbol is only a label; it is the contract address that tells the wallet which balance to show.

What if the balance or transfer is missing?

Start with the transaction hash, not repeated bridge attempts. If there is no Sepolia transaction yet, the cross-chain process may still be pending or the source transaction may not have completed. If the transaction failed, inspect its status and return to the bridge interface for its stated next step. If it succeeded but the transfer event lists another recipient, the tokens went to that address.

Once the explorer shows a successful transfer from the expected token contract to your Sepolia address, the on-chain arrival is confirmed. If the wallet balance still differs, refresh the wallet or import the verified token contract. That separates a display problem from a transaction problem and gives you a concrete record to use when checking the bridge result.
