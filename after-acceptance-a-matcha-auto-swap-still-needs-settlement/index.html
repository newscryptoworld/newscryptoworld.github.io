After Acceptance, a Matcha Auto Swap Still Needs Settlement

What happens after a solver accepts a Matcha Auto swap? The solver arranges execution, and tokens arrive only after the onchain transaction settles successfully.

Crypto Record EditorialNov 19, 2026 · 02:25 UTC3 min read

After a solver accepts a Matcha Auto swap, the signed intent moves into execution; the trade is complete only when its transaction settles onchain.

Acceptance hands the signed intent to execution

Acceptance means a solver has won the opportunity to execute the trade, not that the user has received the output tokens. The user’s signed intent states the exchange they want, including the minimum amount of token B they will accept for token A.

Solvers compete to provide a valid execution for those terms. Once one accepts, it arranges the trade using the signed intent. The transaction still has to be submitted to the blockchain and included in a block before the exchange can settle.

Think of acceptance as a handoff: the winning solver takes the order into the execution stage, where the onchain transaction must carry out the signed terms. When checking a Matcha swap, look for transaction submission after acceptance before counting the output as received. That distinction also helps explain how solvers compete to fill Matcha swap orders.

In an eligible gasless flow, the 0x Gasless API can bundle a token approval and the swap into one transaction. A relayer submits that transaction, and 0x fronts the gas; the gas cost is included in the traded token. This describes how gas is handled for eligible flows, rather than a guarantee that every order uses the same route.

Settlement credits token B to the user

Onchain settlement is the point at which token A is exchanged and token B is credited to the user’s address. Until that transaction settles, acceptance or a pending transaction is an earlier step in the process.

Consider an illustrative case: Mira signs an intent to exchange token A for at least the amount of token B stated in her order. A solver accepts the order and arranges execution under those terms. For an eligible gasless transaction, the relayer submits the bundled approval and swap. The chain processes the transaction, and once it settles, Mira’s address receives token B.

The sequence is therefore: Mira signs the intent, solvers compete, one solver accepts and arranges execution, a relayer submits an eligible gasless transaction, and the chain executes and settles it. The result is token B at Mira’s address. A pending transaction has not reached that result yet.

This distinction is useful when deciding whether funds are ready for another trade or payment. Acceptance tells the user that a solver has taken the order into execution; a submitted transaction shows that execution is underway onchain; confirmation marks settlement. For a decentralized exchange aggregator, the route through liquidity sources can vary, but the user’s practical check is the same: wait for settlement before treating the output as available.

Why is a Matcha Auto swap still pending?

A Matcha Auto swap can remain pending after acceptance while its transaction awaits onchain inclusion and settlement. Acceptance is the solver’s win of the opportunity to execute; it does not show that the chain has completed the exchange.

Who pays gas for a Matcha Auto swap?

For an eligible gasless flow using the 0x Gasless API, 0x fronts the transaction gas and includes its cost in the traded token. The API can bundle an eligible approval and swap in one transaction, which the relayer submits.

After the transaction settles, check the token B balance or transaction record at the receiving address. That confirms the output and gives the user a clear point from which to decide what to do with the received tokens.
