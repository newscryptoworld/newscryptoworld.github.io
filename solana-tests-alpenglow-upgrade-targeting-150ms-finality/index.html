Solana tests Alpenglow upgrade targeting 150ms finality

Solana’s Alpenglow consensus upgrade is live for testing on its public testnet, targeting 150-millisecond finality while leaving transaction execution unchanged.

Chain News NewsroomSep 24, 20262 min read

Solana’s Alpenglow consensus upgrade is live for testing on its public testnet, targeting finality in about 150 milliseconds instead of the roughly 12.8 seconds required by the current system. The change could let exchanges credit deposits and bridges release assets sooner, but the target is not a confirmed mainnet result: Solana’s Alpenglow upgrade page lists the feature as live on testnet and not activated on mainnet.

How does Alpenglow change Solana’s current finality process?

Alpenglow replaces TowerBFT’s on-chain voting with Votor, a protocol in which validators send votes directly to one another and aggregate them into certificates. According to the Solana Foundation, a block can become final after one or two rounds of voting. Under TowerBFT, validators’ votes are recorded as transactions, and votes stack over 32 slots before finality—about 12.8 seconds.

The distinction matters for services that need to know a transaction cannot be reversed. Faster finality could shorten the wait for an exchange deposit to be credited or for a bridge to release funds on another network. The roughly 150-millisecond figure is a target based on testing, not a fixed guarantee; the Foundation says actual time depends on stake distribution and whether finality takes one or two rounds.

What changes for users, and what remains different for operators?

Wallets and applications do not need to change how they send transactions, and execution, programs and fees remain untouched, according to the Foundation. The consensus layer changes underneath. That leaves developers and operators with migration work: Solana’s upgrade notes flag changes to block data and streaming, including the removal of vote transactions from blocks.

The first test also has a narrower software base than Solana’s longer-term validator mix. CoinDesk reported that the initial migration requires Agave 4.3, Anza’s Solana validator software, while Jump Crypto’s alternative clients Firedancer and Frankendancer do not yet support Alpenglow. Those clients are intended to add software diversity; their absence means the initial test does not establish how the new consensus works across those alternatives. The CoinDesk report on the testnet rollout also noted that a September 28 Agave feature-activation date was tentative, not a confirmed Alpenglow mainnet launch.

What should validators and users watch next?

The key signals are whether the testnet migration remains stable, whether alternative validator clients add support, and when Solana schedules mainnet activation. The upgrade also changes consensus assumptions: the Foundation says Votor is designed to tolerate up to 20% malicious stake plus 20% offline stake while reaching consensus. That model and the speed target still need to be evaluated through testing and adoption. Until Alpenglow activates on mainnet, TowerBFT’s longer finality remains the live standard for users and services.
