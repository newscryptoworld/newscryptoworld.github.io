Solana Tests Alpenglow Upgrade Targeting 150ms Finality

Solana has activated Alpenglow on testnet, where validators will test a new voting protocol targeting 150-millisecond finality instead of 12.8 seconds.

The Crypto Daybook EditorsSep 24, 20262 min read

Solana has activated Alpenglow on its public testnet, beginning tests of a new consensus system that targets transaction finality in about 150 milliseconds, down from roughly 12.8 seconds. The Solana Foundation’s Alpenglow upgrade page lists testnet activation as active and the 150-millisecond figure as a target; the change is not yet active on mainnet.

Alpenglow changes how validators agree that a block is final. It leaves transaction execution, programs and fees unchanged. The public testnet gives developers and infrastructure providers a place to check the new consensus process before any mainnet activation.

How will Alpenglow change validator voting?

Alpenglow replaces Solana’s current TowerBFT consensus with a voting protocol called Votor. Under TowerBFT, validators record votes as transactions, and enough votes accumulate over 32 slots before a block is final. The Crypto.news report on the testnet move describes the shift to validators exchanging votes directly.

Votor bundles those votes into certificates. Validators can finalize a block after one or two voting rounds, instead of waiting for the longer sequence of on-chain votes. It is like replacing a queue of separate approvals with a group decision: the validators still have to agree, but the protocol collects and records their agreement differently.

What does the 150-millisecond target measure?

It measures the time for a transaction to become final under the consensus rules: the point at which it can no longer be reversed. It does not mean Solana will produce a block every 150 milliseconds. The Foundation says block times are being reduced separately, in stages, from 400 milliseconds to 200 milliseconds.

The faster finality remains a target to be tested. The current testnet stage lets teams check the migration and look for problems in a testing environment before the upgrade is considered for mainnet. Transaction execution itself does not change, but applications and infrastructure that read block or vote data may need to adapt.

When could Alpenglow reach mainnet?

There is no confirmed mainnet activation date on the Foundation’s upgrade page. It lists Alpenglow as in development, with testnet active and devnet and mainnet not yet activated. Its planned rollout puts Votor first; a separate phase called Rotor is intended to replace Turbine, Solana’s block-propagation system, in a later release after Votor is adopted.

For now, the result to watch is whether validators can complete the new voting process reliably across test environments. The 150-millisecond figure describes the intended outcome. Testing will show whether the protocol can deliver it before mainnet activation.
