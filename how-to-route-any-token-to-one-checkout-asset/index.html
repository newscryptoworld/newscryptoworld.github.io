How to Route Any Token to One Checkout Asset

To accept payments in any token from any chain in your app, quote into one settlement token, track delivery, and credit the order only after destination confirmation.

Crypto Record EditorialNov 28, 2026 · 07:29 UTC4 min read

To accept any token from any chain in your app, route each payment into one settlement token on one chain and credit the order only after the destination contract confirms receipt. Start with an order ID and settlement address, quote the payer’s token, request approval and signature, then track delivery. The order is paid when the expected amount reaches the settlement contract.

What should be ready before checkout?

Choose the settlement token, destination chain, and receiving contract before requesting a quote. Set each order’s price in that token, such as USDC on Base, so your app can compare the amount received with the amount due.

Jumper bridge is built on LI.FI, whose API and SDK return route quotes and transaction data. Use Jumper bridge routing to find a supported path from the payer’s asset to your settlement asset, and check that the quoted route ends at the address and contract your checkout expects. The LI.FI Widget can provide a ready-made transaction interface; the SDK gives your app more control over the checkout flow.

Your settlement contract must be deployed on the target chain and able to receive the routed token. For order-level tracking, it also needs a destination call that records the order ID when funds arrive. That contract is a dependency for the next stage: without it, the route can deliver funds, but the app has no on-chain order reference to verify. You’re ready when a test call can send the settlement token to the contract and associate it with an order ID.

How do you route and confirm each payment?

  1. Request a quote. Send the payer’s fromChain, fromToken, fromAddress, the destination toChain, toToken, toAddress, and an amount. The quote shows a route and the amount and fees the payer can review. Use an exact-output quote where supported, so the requested output matches the order price.
  2. Prepare the destination call. Include the order ID in the call that the route makes to your settlement contract. The contract should record the order ID and the amount received. This is like putting a reference number on a bank transfer: your app can match delivery to a specific order instead of guessing from the amount sent to a shared address.
  3. Request approval and signature. When the source token needs an allowance, have the payer approve it, then ask them to sign and send the returned transaction. Save the source transaction hash against the order. The payer sees a submitted transaction, and your backend has the identifier it needs to follow that transfer.
  4. Track the route. Use LI.FI’s status endpoint with the transfer details and keep checking while the status is PENDING. Wait for DONE before checking destination-chain delivery. A transaction can take varying time depending on the route and chain, so elapsed time alone is not confirmation.
  5. Verify and credit. On DONE, verify the destination transaction, contract event or recorded order, and amount received. Credit the order only when the settlement contract has recorded the expected payment. The visible result is an order marked paid with a matching settlement balance.

What happens when a route fails or takes longer?

An expired quote, slippage failure, or refund to the payer leaves the order unpaid. Show the payer what happened, keep the order open, and request a fresh quote before they try again. A FAILED status is a signal to investigate the route outcome; verify whether funds were refunded or delivered before changing the order state.

For a USDC route, Circle CCTP can use native USDC burn-and-mint settlement across supported chains. It is one possible route component, not a guarantee that every payer token or chain is supported. The quote determines whether a route is available for the selected source and destination.

Related

Can a payment contract receive a bridged token through a contract call?

Yes, when the selected route supports a destination contract call and the contract accepts the settlement token. Include the order ID in that call and verify the contract’s recorded receipt before crediting.

How long should a crypto checkout wait before marking a payment failed?

Keep the order unpaid while status is PENDING; don’t mark it failed just because a timer elapsed. Mark it failed after the transfer reports FAILED and you have checked for a refund or late delivery.
